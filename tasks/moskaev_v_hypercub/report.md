1. Введение
Цель работы — реализовать гиперкубовую топологию с использованием MPI без использования встроенных функций MPI_Cart_Create и MPI_Graph_Create, обеспечив корректную коммуникацию и вычисления.

2. Постановка задачи
Требуется реализовать виртуальную гиперкубовую топологию для произвольного числа процессов, являющегося степенью двойки. Задача включает:

Проверку корректности гиперкубовой топологии
Организацию коммуникации между процессами-соседями в гиперкубе
Реализацию алгоритма глобального суммирования на гиперкубе
Тестирование производительности и корректности работы

Входные данные:

test_size: количество случайных чисел для суммирования на каждом процессе
seed: seed для генератора случайных чисел
test_communication: флаг тестирования коммуникации
test_computation: флаг тестирования вычислений

Выходные данные:
topology_verified: успешность проверки топологии
communication_ok: успешность проверки коммуникации
computation_ok: успешность проверки вычислений
total_tests_passed: количество пройденных тестов
max_hops_required: максимальное количество хопов для коммуникации

4. Схема параллелизации
Организация гиперкуба
Каждый процесс получает ранг от 0 до (N-1), где N — степень двойки

Процессы-соседи определяются побитовым XOR с масками степеней двойки

Размерность гиперкуба: log₂(N)

Алгоритм суммирования на гиперкубе
Каждый процесс вычисляет локальную сумму случайных чисел

Для каждой размерности гиперкуба (0..dimensions-1):

Определение партнёра: partner = rank ^ (1 << dim)

Если партнёр существует (partner < size):

Процессы обмениваются частичными суммами

Каждый процесс добавляет полученную сумму к своей

После всех обменов каждый процесс содержит глобальную сумму

7. Результаты и обсуждение
7.1 Корректность
Корректность реализации проверяется через:
Проверку топологии: убеждаемся, что каждый процесс имеет корректных соседей
Проверку коммуникации: тестируем передачу данных между крайними процессами
Проверку вычислений: сравниваем глобальную сумму с эталонным значением
Все функциональные тесты (comm_only, comp_only, full_test) успешно проходят для последовательной и MPI-версий.

7.2 Производительность
Результаты тестирования производительности:


Количество процессов	Время, с	Относительное время	    Эффективность
        2	            0.017	        1.00	            100.0%
        4	            0.029	        1.71	            42.8%
        8	            0.061	        3.59	            44.9%


Примечания:

Базовым значением для сравнения взято время выполнения для 2 процессов (0.017 с)

Эффективность рассчитывается относительно идеального случая: время должно уменьшаться пропорционально увеличению вычислительной мощности

Анализ результатов:

Увеличение времени с ростом числа процессов:
При переходе от 2 к 4 процессам время увеличивается в 1.71 раза
При переходе от 2 к 8 процессам время увеличивается в 3.59 раза

Основные причины деградации производительности:
Коммуникационные накладные расходы: Каждый дополнительный процесс добавляет новые каналы связи
Барьерная синхронизация: Алгоритм использует MPI_Barrier после каждого измерения гиперкуба
Алгоритмические особенности: Гиперкубовое суммирование требует O(log N) шагов коммуникации
